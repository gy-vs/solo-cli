## Phase 9 · 详情页卡死与重启后遗症（用户反馈）

- [x] P9-2 事件接口加尾部上限：SSE 默认回放最后 600 条并先发一条 `truncated` 告知总数，`events/list` 支持 `limit`；历史脏数据已清理（46843 → 204 条，库 16MB → 964KB）。
- [x] P9-3 结束状态判定抽成 `runner.decide_status`：后端重启后接管的容器读不到 stdout，`result` 恒为空，退出码 0 的题会被误判成 FAILED（实测题 06 跑了 63 分钟、60 次工具调用、改了 3 个文件仍标记失败）。现在退出码 0 且本轮有轨迹即算完成，并在 notes 说明轮次与用量为空；补 6 项单测覆盖各分支。
- [x] P9-4 启动自愈 `pipeline.resume_stale()`：分析与质检是进程内的活，后端一重启状态就永远卡在「分析中」。启动时复位中断状态并把没走完的题重新排进流水线。

## Phase 14 · 详情页的「终端」不是终端（用户反馈）

- [x] P14-1 终端改成真终端：原来点开只是 `docker logs -f` 的只读回放，看得见模型往外写什么，却问不了它任何问题 —— 而「模型此刻把工作区改成了什么样」这件事，收尾前界面上根本不存在，只有进去 `git status` 亲眼看一遍才算数。新增 WebSocket `GET /api/tasks/{id}/container/exec`，后端开一个 pty 接 `docker exec -it`，前端换成 xterm.js；日志降为同一个抽屉里的第二个视图，默认进终端。实测：真 TTY（`/dev/pts/2`）、彩色提示符、行编辑、窗口改大小容器里跟着变、中文不被切碎，在跑着的题里直接看到 `M lib/root.js`、`?? lib/patch.js`。
- [x] P14-2 用完的 shell 要收掉：杀掉本机那个 `docker exec` 客户端进程，容器里的 shell 不会跟着死 —— 对 daemon 来说两者没有从属关系，客户端没了它照样在自己的 pts 上等输入。实测每开一次终端就在容器里留一个 bash，而终端里跑过的长命令会一直跑下去，那是一道正在评测的题。改为让 shell 先把 PID 写到 `/tmp`（工作区和轨迹是产物，一个字节都不能写），断开时照着发 SIGHUP，冲进程组发，把它起的子进程一起带走。实测开关抽屉、切换视图、换侧各条路径走下来，容器内 shell 数每次都回到 0，终端里 `sleep 987 &` 起的后台进程也一并消失。
- [x] P14-3 配套：nginx 同一个 `/api/` 要同时伺候 SSE 和 WebSocket，按 `map $http_upgrade` 分流（SSE 必须拿到 `Connection: ""`，ws 要 `upgrade`），实测三条 SSE 无回归；容器不在、已退出、side 非法一律先握手再发原因关连接 —— 在握手阶段拒绝的话浏览器只会给一个「连接失败」，人分不清是容器没了还是后端挂了；容器名一律由 `task_id + side` 推算，不接受调用方传，否则这个能执行任意命令的接口等于把宿主机上所有容器都开放了。

## Phase 15 · 题库收到远端，领取跨设备互斥（用户反馈）

- [x] P15-1 一个仓库同时当题库与查重池：`pool.Entry` 新增 `draft`（整份题面 Markdown）。此前池里只有 prompt 正文，够查重但不够领题 —— 仓库地址、初始快照、语言、Harness 版本、可复现等级全在题面的字段区里，缺了它另一台设备拿到的只是一段没有出处的文字。出题落地时顺带入池，并在仓库里写一份 `prompts/<设备>/NN.md` 供人直接阅读。
- [x] P15-2 领取归属记在远端：新增 `claims.jsonl`（append-only + `merge=union`），一次领取或释放一行。归属由 `owners()` 把全部动作按 `(时间, 设备, 动作)` 排序重放算出 —— 先 claim 的赢，release 只认本人发的。排序键不含行号，两台设备读同一份文件必然算出同一个归属，不需要中心仲裁。

### 修掉的真实缺陷

- 设置页「保存全部」会把界面掩码写回库里，密钥当场作废（容器报 `Header '14' has invalid value: 'Bearer ••••••••r0QA'`）。掩码比较改为前缀判断，前端不再提交掩码，启动时清理被污染的值并提示重填。
- 轨迹目录按题号复用，一次没产出轨迹的运行会捡起上一轮的 jsonl 当成自己的，把旧 SessionID 回填进 `prompt.md`。改为只认本轮开始之后写过的文件。
- 池不可用时领取直接放行，跨设备独占静默失效。`claim_remote` 走到时这道题一定来自远端题库（纯本机题在 `_take_remote` 就返回了），另一台设备同样看得见；池被关掉或仓库、本机标识、Token 缺任一项就绕过登记开跑，两台设备各做一遍同一道题，产物推去同一个仓库的同一个分支。题 158 就是这么废的：远端 `A` 上挂着另一台设备推的 `solo 158-gaoyong · A`，本机做完的那一跑再也推不上去。改为一律拒绝并说明缺什么。
- push 被判 non-fast-forward 时只说「远端这个分支已经领先本地了」。这一侧从初始快照起只提交过一次，本地没有可拉的东西，人对着干净的工作区无从查起。改为这一类失败额外 fetch 一次远端那个分支，把对方提交的 sha 与标题读出来 —— 产物提交的标题带着题号和侧别，一眼看得出是哪台设备在做同一道题。

## Phase 17 · 提交前质检：核验放行的理由仍然不像人说的话（用户反馈）

- [x] P17-1 新增 `services/gsb_precheck.py`，把「机械化表达」提炼成十条规则交给模型逐句读。与 `gsb_verifier` 分工清楚：那道核验查的是正则判得出的东西（字数、步号、行号、markdown），这道查的是措辞和句子本身 —— 用户举的三个例子（「题面对错误载荷写得很具体：超限时要能看出是步数还是深度」「根因两边翻到的是同一处」「B 有一处确实比 A 想得远」）每个字都合规，核验一路放行，可是没有人会这么说话。规则分十类：转述材料、动作化动词、拟人化评价、含糊限定、冒号夹注、句子生硬、比喻指代、随口俚语、生造省略、刻意口语。
- [x] P17-2 判断基准（`JUDGE_BASELINE`）摆在规则前面，且必须是这个顺序。少了它模型会把「机械化」理解成「太正式」，转头往里加语气词，交回来的东西更不像评审意见 —— 用户给的三个改法（「题目明确要求」「两边对问题的定位是一致的」「B 在接口设计上比 A 更合理」）全都比原文更书面，基准里把这一点连着反例正例一起写死。
- [x] P17-3 本地词表先摘一遍疑似句塞进 prompt，但不做独立判定。一段五六百字的理由里这类词往往只有两三处，不点出来模型容易整体读一遍回一句「还行」；词表只收明显的，「不太」「略」「算是」这类日常里本就自然的词一个不收 —— 摘得越多模型越不当真。实测题 219 那段 977 字的理由本地一处没摘到，模型仍挑出 8 处，两者互补。
- [x] P17-4 三道采信关，每一道都对应一次真实的翻车：① quote 对不上原文的条目整条丢掉（模型会把自己改写后的句子填进 quote，人按它去正文里找，找不到，只能整段重写）；② 结论按 issues 定不按模型自报的 verdict 定（它常常一边列三条问题一边说 pass，反过来也有）；③ 整段改写稿要过篇幅和红项两关（把一千字压成两百字、改写时带进一条 markdown，套进去之后核验才报红，比没有这份稿子更费事）。
- [x] P17-5 质检只报问题、不改文字。自动改的话，人下次打开看到的已经不是他确认过的那一段，而差异藏在几百字里翻不出来。改写稿摆在界面上，点「填进理由」只动编辑框，落库还要再点一次保存。
- [x] P17-6 新增题级状态 `QC`，`UPLOADABLE` 收窄成只有它。录屏齐不齐决定题落在 `ANALYZED` 还是 `QC`，由 `sync_stage` 一处投影（填链接、代传录屏、重新分析完成、开机对账四个入口都走它），不让各个动作各写各的 —— 那样迟早留下一批录屏齐了却挂在待录屏栏的题，而人正是照着栏目决定下一步做什么。
- [x] P17-7 提交门禁收敛到 `submit_block` 一个函数，状态、质检结论、结论有没有在质检之后被改过三件事一起判，返回一句人话。前端按钮灰不灰、`upload_task` 回绝的理由、CLI 打印的原因全取这一句，不在三个地方各凑一套条件。判定用白名单（只有 `PASS`/`CONFIRMED` 放行）：`ALTER TABLE` 补出来的列是空串，黑名单式的判断会把库里 152 道老题全当成质检通过。
- [x] P17-8 质检结论只对当时那一段话负责：落库时连着理由正文的指纹（去空白后的 sha256 前 16 位）一起存，人又改了一稿就算过期，提交重新被挡。人工确认时把指纹换成此刻这一稿 —— 否则一确认就立刻显示「已过期」。
- [x] P17-9 发起入口只有 `app/cli.py`（`ready` / `precheck` / `status` / `submit` 四个子命令），nginx 把 `/api/tasks/(batch|\d+)/precheck` 一并挡成 403，前端的 `api.ts` 里也没有对应封装，只留「人工确认放行」。挡在 nginx 而不是只靠「前端不放按钮」：这条流程要在人看过录屏、准备整批提交的那一刻跑，跑早了理由还会改、结论当场过期，一个点一下就烧掉一次模型调用的按钮摆在页面上迟早会被点。CLI 打后端进程的 HTTP 口而不是自己 import service 跑 —— 事件总线是进程内的，另起进程写库浏览器收不到事件，人盯着列表看不见「质检中」。
- [x] P17-10 界面：列表页新增「质检」栏，把横着比的那一列从「A/B 用时」换成质检结果（到这一步对比结论早写完了），批量条给「批量提交」，被挡下的题当场列出题号和原因而不是悄悄跳过；详情页新增「提交前质检」页签，逐条给原句（橙色左边框）和改法（绿色左边框），带整段改写稿和人工确认区；没质检过的题不给按钮，直接把该敲的命令印出来。总览把质检没放行的题并进「等我处理」。
