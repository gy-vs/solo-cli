# 录屏录制处理 · 自动化设计

把「待录屏 → 手动调 /solo-report → 发 MD 给别人 → 收视频 → 贴路径 → 提交」这一段做成流水线。
出题端（本机与另一台出题设备）自动生成录屏文档并发布，录屏端在控制台上拉取、录制、回传视频，
出题端自动收回视频，题进「可上传」，人最后点一下提交。

## 角色

| 角色 | 部署 | 做什么 |
|---|---|---|
| 出题端 | 本控制台（现有两台设备） | 待录屏的题自动生成 `report.md` 并发布到录屏仓库；巡检收回录好的视频；可上传的题一键提交 |
| 录屏端 | 同一套控制台，设置里打开「本机只做录屏」 | 只用「录屏录制处理」页：看队列、拉取文档、录制、上传视频 |

两端靠同一个 GitHub 私有「录屏仓库」协作，与跨设备题库同一个思路：没有公共后端，gh token 本来就要配。
设备标识沿用 `pool.device`，发布与回传都带着它，谁出的题、谁录的视频一眼分得清。

## 录屏仓库布局

```
main
  .gitattributes        events.jsonl merge=union
  events.jsonl          一个动作一行，append-only
rec/<设备>/<题号>       每道题一个孤儿分支
  report.md             录屏文档（skill 模板：仓库、A/B 两侧 PowerShell 命令、界面操作）
  meta.json             题号、设备、仓库地址、结论、生成时间、报告指纹
  A.mp4 / B.mp4         录屏端回传的视频（720p 每个约 3 MB，直接进仓库，不用 LFS）
```

每题一个分支而不是全放 main：main 只装几 KB 的事件流，两端每轮巡检拉它很快；视频只有真要用的那一端才去拉那一个分支；
题提交后删分支，仓库不会越涨越大。每道题的**作答仓库**有平台规则 G2（只许 main/A/B 三个分支），
所以文档和视频绝不能放进作答仓库，只能放在录屏仓库里。

### 事件

| type | 谁写 | 含义 |
|---|---|---|
| `published` | 出题端 | 文档已生成并推到分支，可以录了；重新生成会再写一行，带新指纹 |
| `claimed` | 录屏端 | 点了「拉取」，这道题由我来录；先写先得，同 `claims.jsonl` 的仲裁规则 |
| `released` | 录屏端 | 不录了，放回队列 |
| `recorded` | 录屏端 | 两侧视频都已推到分支 |
| `collected` | 出题端 | 视频已收回并代传平台 |
| `withdrawn` | 出题端 | 题离开待录屏（理由被改、废弃、已提交），这份文档作废 |

状态按时间戳重放折叠，与行序无关：`published → claimed → recorded → collected`，任何时刻出现更晚的 `withdrawn` 就回到作废。
`withdrawn` 之后重新 `published`（理由改了、重新质检过）会开始新一轮，旧的 claim 与视频一并作废。

## 题级状态

新增 `READY`（可上传），插在 `QC`（待录屏）与 `UPLOADED` 之间：

```
ANALYZED 待质检 ──两道质检放行──▶ QC 待录屏 ──两侧录屏链接齐──▶ READY 可上传 ──人点提交──▶ UPLOADED
      ▲                            │                                  │
      └──────── 理由被改、质检过期 ───┴──────────────────────────────────┘
```

投影仍然只在 `gsb_precheck.sync_stage` 一处做。`READY` 与 `QC` 一样可以提交（`UPLOADABLE`），也一样受质检过期约束（`SETTLING`）。

## 文档生成（出题端，后端编排）

规则只在 `~/.cursor/skills/solo-report` 这一份里，本项目不留副本。确定性步骤由后端直接跑 skill 自带的脚本，只有写片段这一步问模型：

1. `collect.py --task <题号> --all`：Prompt、GSB 结论与 findings、两侧形态探测、轨迹里跑成功过的命令与真实输出。
2. 把 SKILL.md、片段模板、PowerShell 规则与这道题的素材一起交给 Cursor CLI（问答模式，不放开 shell），要它只输出一段片段。
3. `verify_ps.py` 四层校验（静态规则、真实 PowerShell 解析、内联脚本引号、存文件脚本语法）。不过就把报错原样喂回去重写，最多 3 轮；
   3 轮仍不过就记失败留给人看，不发布半成品。
4. 套上文档头写成 `report.md`，推到 `rec/<设备>/<题号>`，写 `published`。

`verify_ps.py` 调 `docker run -v` 挂的是后端容器里的临时目录，宿主机 daemon 找不到。后端用包装器把挂载源翻译成宿主路径
（临时目录落在 `DATA_DIR` 下，脚本目录翻译到 `SKILL_DIR_HOST`），脚本本身不改。

并发走 `rec.max_parallel`（默认 2），与分析、质检的额度分开记：写片段一次十来分钟，挤在分析额度里会让新跑完的题等录屏文档。

## 视频回收（出题端，巡检）

每轮巡检拉一次录屏仓库 main，本机设备名下出现 `recorded` 而没有 `collected` 的题：拉那个分支 → 两个视频走现有 `upload_screencast`
（收进题目目录、代传平台、写链接）→ 写 `collected` → `sync_stage` 把题推到 `READY`。

题离开待录屏（废弃、已提交、理由被改退回待质检）时写 `withdrawn`；已提交的顺带删分支。

## 录屏端操作

「录屏录制处理」页三个分栏：**待录制**（所有设备发布的、没人认领的）、**我在录**、**已回传**。

- 拉取：写 `claimed` 抢占，成功后在页面上渲染 `report.md`（命令一键复制，也能下载 md）。被别人抢先时当场提示并刷新。
- 上传视频：浏览器选 A、B 两个文件（或填本机路径），后端推到那道题的分支，两侧齐了写 `recorded`。
- 放回：写 `released`，别人可以接着认领。

出题端看到的是同一页的另一组分栏：**生成中 / 生成失败**、**待录制**（已发布，等人认领）、**录制中**、**已回传待收**、**可上传**。
可上传那一栏给「提交」与「批量提交」，最后一步留给人确认。

## 设置

| 键 | 默认 | 说明 |
|---|---|---|
| `rec.enabled` | 关 | 启用录屏协作 |
| `rec.repo` | 空 | 录屏仓库 `owner/repo`，不存在自动建成 private |
| `rec.recorder_only` | 关 | 本机只做录屏：不自动生成文档、不收视频 |
| `rec.auto_generate` | 开 | 题进待录屏就自动生成文档 |
| `rec.max_parallel` | 2 | 同时生成文档的道数 |
